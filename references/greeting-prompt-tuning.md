# 招呼语 prompt 调优：症状 → 机制 → 改法

`mode=llm` 的招呼语由本地小模型现写。约束没写对时，错误会成类出现，不是偶发。
下表是实测过的失败模式：看到症状先对机制，再只改对应那一层，别整段重写 prompt。

代码位置：`scripts/greet.py` 里 `RULES`（骨架与硬性）、`STYLE_WORDS_HARD` / `STYLE_WORDS`（词库）、
`CLOSINGS`（结尾候选句）、`check()`（闸门）。配置旋钮在 `user.greeting.*`。

| 症状 | 机制 | 改法 |
|--|--|--|
| 满篇「具备 / 赋能 / 闭环 / 沉淀 / 深耕」 | 小模型默认语料就是简历和 PPT | 两级词库：`STYLE_WORDS_HARD` 命中一个就重写；软词（高效/深度/能够）允许 1 个。同时把 facts 里的同类词改写掉（模型会照抄事实的措辞） |
| 三句排比、句句带 KPI、读着像摘要 | 「自由发挥 + 挑 2–3 条成绩」没给结构 | 骨架写死：开场→两条成绩（哪家公司/城市 + 做了什么 + 结果）→用 JD 原词呼应→固定结尾；`max_numbers=6` 卡住堆砌 |
| 「你做这行 N 年了吧」——候选人的经历被写成招聘方的 | 一旦要求口气像「同行老同事发微信」，模型会乱用人称 | 显式人称段：只准「我」指候选人、「您/你们」指招聘方；禁反问、禁「吧/呢/吗」收尾。语气类要求必须配人称约束，不能单独加 |
| 「想聊聊」「简单聊聊吗。」这种半截话 | 结尾由模型自由生成，它会省字 | `CLOSINGS` 三句由代码 `random.choice` 注入、要求原样照抄，闸门 `bad_closing` 校验。让模型「三选一」时它几乎总选第一句，分布不均 |
| 85% 写成「加一五」、-30% 写成「三十天」、翻倍 | 模型把数字口语化后，阿拉伯数字溯源闸门（只匹配 `\d+`）形同失效 | `CN_NUM_RE` 拦中文数字串（单字「一年/四城」放行）+ prompt 明说「单位不许换算，原文照抄」 |
| 字数冲到 205–220，超 200 被判 `too_long` | 四段骨架 + 固定结尾本身就吃字数 | prompt 加「写完自己数一遍，超了删一条成绩」；`llm.retries=2`（三次机会）；真降不下来就把 `length.max` 放到 220，别让回退变常态 |
| 「我在 X 上做过搭出 SOP」这种绕口句 | 「我在…做过」是模型最爱的填充句式 | prompt 明禁「我在 X 上做过」和动词连用（做过搭出/做过搭建），要求直接说做过什么 |
| 每条都一模一样、成绩反复是同一组 | 同岗位命中缓存；或温度太低 | 调优期一律 `--no-cache`；`temperature=0.75`、`top_p=0.9` 比 0.7 更自然 |
| 把示例整段抄进正文（连示例里的数字一起） | 给出完整范文当 few-shot | 只给骨架和「必须规避的句式」，不给可直接复制的成品范文；要例子就给反例（错的那种） |

## 调优循环

1. 改 `RULES` / 词库 / `CLOSINGS` 任意一处，就把 `PROMPT_VERSION += 1`。
   缓存键含版本号，不升版会继续发旧话术，改了半天看不到效果。
2. 回归：`greet --job-name … --jd-file … --no-cache --times 6`（换两个风格差异大的 JD 各跑 6 条）。
3. 判据三条：过闸门率 ≥5/6；每条 100–200 字；人读一遍——像不像真人手打的，这条最重要，闸门测不出来「读着自然」。
4. 有回退就看 `回退原因`：`too_long` / `too_many_numbers` / `ai_style_hard` / `cn_numbers` / `bad_closing`
   各自对应上表一整行，只改那一层。
5. 改完跑一次 `preflight` 确认 `招呼语 … ok:<模型>`，再让真实入口（定时 wrapper）跑一轮。

## 边界

- 闸门只能拦住「可机械判定」的毛病（字数、词表、数字、结尾、分号、人称的痕迹）。
  「这段话有没有人味」必须人读，别因为闸门全绿就交付。
- 招呼语是给具体 HR 看的第一条私信，宁可短、具体、说清在哪家公司做过什么，不要面面俱到。
- 别为了让闸门容易通过而放宽阈值（比如把 `style_hits_max` 调到 3、`max_numbers` 调到 10）：
  过闸门率好看，发出去的话术又回到简历体。
